# GitHub owner release implementation plan

Approved inputs: the session-approved release proposal and [spec](../specs/2026-10-12-github-owner-release.md). Standard security profile remains unchanged. Work is isolated from the user's dirty original checkout.

1. Worker A owns scripts/artifacts/owner_release.py and tests/artifacts/test_owner_release.py: strict schema-3 parsing, deterministic non-circular approval payload/body, live PR/Git tree/main/owner/environment/CI validation. Write acceptance and rejection tests first, demonstrate RED, implement, then GREEN. API: parse_owner_receipt(payload, source_sha, allow_unapproved=False); approval_body(receipt); validate_live(receipt, actor_id, workflow_sha, root, api=None). Reuse read-only github_api and required CI job constants from owner_approval; never alter the schema-2 module.
2. Worker B owns scripts/artifacts/owner_release_export.py and tests/artifacts/test_owner_release_export.py: validate ordinary/partitioned historical review packages and actual Standard security-assessment records; produce unapproved draft receipt without overwriting files. Input source/workflow merge SHA and PR numbers, original review packages, actual assessment files, exact versions, four run IDs; resolve all identity from Git/evidence. Require source/workflow ancestry and tree proofs, current clean checkout, zero findings. Never call a reviewer or publish. Import core validator only when available; coordinate fields through the approved spec.
3. Primary owns scripts/artifacts/release_receipt.py, scripts/verify-artifacts and their routing tests: route only schema 3 to new validators; add explicit draft/finalize CLI; enforce positive owner comment and actual receipt checksum before publication. Keep old routes and workflow write boundaries intact. No source or version hardcoding that could silently authorize a future receipt.
4. Primary updates release/threat/architecture/project-model docs; generate docs, never edit generated HTML manually. Record approval mode and residual risks honestly.
5. Run focused and related regression tests, artifact/runtime suite, quick gate. Commit exact scope; push draft governance PR and let native/full-suite CI run. Build immutable bounded workflow review package for AGY; obtain its exact manifest approval and validate review output. Run canonical merge gate, merge only after pass.
6. Preserve historical source evidence and reviewed workflow evidence. Generate source-bound draft receipt from real completed CI, security assessment and merge proofs. Obtain exact owner approval before recording the approval comment/final receipt. Dispatch package workflow on its reviewed main revision, approve protected deployment only as authorized, verify both native builds/scans/signatures/pulls. Record image/chart digests and prepare final operator values once real inputs exist.

Rollback: keep schema-1 and first-release schema-2 behavior unchanged. Disabling/reverting the new schema rejects new receipts before writes. Partial registry publication remains a failed release and follows the existing artifact rollback runbook; never overwrite version/source tags or forge clearance to recover.
