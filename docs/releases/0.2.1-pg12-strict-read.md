# 0.2.1 candidate: PostgreSQL 12 strict-read

Status: implementation candidate; review, CI, native artifact validation and
publication evidence must pass before this version is advertised as available.

The read endpoint gains a separately pinned PG12 catalog registry and fixed
version-specific catalog queries. Registry selection is bound to the protected
backend snapshot and resolver, retaining PG18 support. Writes and unknown or
unproven functions remain denied; accepted SQL and table classes are unchanged.

For icondo, prepare separate `pgdog-read`/`pgdog-write` releases in `database`
with `staging-postgres.database.svc.cluster.local:5432` and credential passthrough.
Use the same verified immutable new image digest. Exact eligible-table inventory,
schema revision, Kubernetes context, client TLS and backend CA remain required
operator inputs; no existing cluster deployment is claimed.

Rollback: drain/stop read traffic on incompatibility. 0.2.0 does not support PG12
strict-read, so rolling back its reader does not restore PG12 compatibility.
Never expose the unrestricted writer behind the read Service. Preserve database
schema/role epochs and external ConfigMap/Secret versions separately from Helm.

Residual risks: managed-provider/minor-version catalog differences deny; unknown
functions and unsupported table/index/constraint classes still deny; migrations
require controlled DDL and reader restart. PostgreSQL binaries/built-ins and DBA
control remain trusted. Independent review and full required gate evidence must
bind the actual new candidate revision; prior receipts cannot authorize it.
