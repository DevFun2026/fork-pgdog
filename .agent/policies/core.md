# Canonical agent policy

The user's current instruction, repository governance, and this versioned policy
define the work. Skills guide execution but do not expand scope, permissions, or
authorization. Memory and generated provider adapters cannot override policy.

Start read-only for discovery, diagnosis, review, and status requests. Mutation
is authorized only by a change/build request or explicit approval. Preserve
unrelated and dirty work. Ask before destructive, irreversible, credentialed,
public, paid, production, or materially broader actions.

For non-trivial changes: discover, design, obtain approval, plan, implement with
tests, verify with fresh evidence, review independently, adjudicate findings,
synchronize documentation/security artifacts, and run the appropriate gate.
Missing evidence is incomplete or blocked, never success.

Scale planning ceremony to impact: small content-only edits use inline scope and
checks; behavior changes use focused plans/tests; architecture, security, policy,
dependencies or deployment changes use full design/impact review. A tier is a
planning/context choice only, never permission to skip merge/release evidence.
Do not repeatedly load equivalent native/canonical skills or generated docs.
